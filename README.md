# Engineering Notes — a minimal Jekyll blog for GitHub Pages

A deliberately small starter. No theme gem, no build tooling beyond Jekyll
itself: every file here is one you can open and understand in a minute.

## Publish it (10 minutes)

1. **Create the repo.** Two flavours:
   - `<your-username>.github.io` → site lives at `https://<your-username>.github.io`, keep `baseurl: ""`.
   - Any other name, e.g. `blog` → site lives at `https://<your-username>.github.io/blog`, set `baseurl: "/blog"` in `_config.yml`.
2. **Copy these files in** and push to `main`.
3. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
   The included `.github/workflows/pages.yml` takes it from there.
4. Edit `_config.yml`: `title`, `author`, `url`, `email`, `github_username`.
5. Replace `<Your Name>` in `LICENSE`.

First build takes a couple of minutes; watch it under the Actions tab.

> Alternative: **Source: Deploy from a branch** also works and needs no
> workflow file — GitHub builds Jekyll for you. The trade-off is that you're
> pinned to GitHub's Jekyll version and its allow-listed plugins. The Actions
> route is now the recommended one and lets you use any gem.

## Write a post

Create `_posts/YYYY-MM-DD-some-slug.md`:

```markdown
---
title: "Your title here"
summary: "One or two sentences shown on the index page and in previews."
tags: [databases, postgres]
---

Your article, in Markdown. Code fences get syntax highlighting.
```

The filename date is what orders the post and builds its URL — it is not
decoration. `layout: post` is applied automatically via `defaults` in
`_config.yml`, so you never write it.

To draft without publishing, put the file in a `_drafts/` folder (no date in
the name) and preview with `bundle exec jekyll serve --drafts`.

## Preview locally (optional)

Needs Ruby 3.x.

```bash
bundle install
bundle exec jekyll serve --livereload
# http://localhost:4000
```

## What's where

| Path | What it does |
|---|---|
| `_config.yml` | Site settings. Changing it requires restarting `jekyll serve`. |
| `index.html` | The article index — a dated log. |
| `_layouts/default.html` | Shell: head, masthead, footer. |
| `_layouts/post.html` | Article wrapper: title, date, tags, licence line. |
| `_layouts/page.html` | Standalone pages like About. |
| `_posts/` | Articles. One file each, `YYYY-MM-DD-slug.md`. |
| `assets/css/style.css` | All styling. Design tokens are at the top. |
| `about.md`, `404.html` | Standalone pages. |
| `.github/workflows/pages.yml` | Build and deploy. |
| `LICENSE` | CC BY 4.0 for prose, MIT for code. |

`/feed.xml` is generated by `jekyll-feed`. Nothing to maintain.

## Obvious next steps

- **Custom domain**: add a `CNAME` file containing your domain, point a DNS
  `CNAME` at `<username>.github.io`, tick "Enforce HTTPS".
- **Tag pages**: a `tags.md` looping over `site.tags`.
- **Comments**: [giscus](https://giscus.app) backs discussions with GitHub
  Discussions — no database, no tracking.
- **Analytics**: if you want any, prefer something cookie-free (GoatCounter,
  Plausible) so you don't need a consent banner.
